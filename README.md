# An Efficient Cloud-Enabled Framework for Smart Agriculture Using Value-of-Information Retrieval and Reservation-Based Scheduling

Code, data pipeline, experiments and manuscript sources for the article
*"Value-of-Information Retrieval and Forecast-Reserved Deadline Scheduling: An Integrated
Framework for Cloud-Enabled Smart Agriculture"* (Sneha, Prabh Deep Singh, Vikas Tripathi),
prepared for *International Transactions on Electrical Engineering and Computer Science* (ITEECS).

FURROW couples two components through explicit signals:

* **FURROW-R** (retrieval, Layer 4) ranks root-zone soil-water sensing units by the posterior
  expected gain of their depletion grade under a staleness model calibrated per depth, month and
  data age, and spends a slack-derived budget of edge polls on the stations whose refresh is most
  likely to change a management-threshold decision (value of information).
* **FURROW-S** (scheduling, Layer 5) orders urgent tasks by laxity and places them by earliest
  finish time including data-access costs, never queues strategic work behind urgent work,
  reserves idle cores from the alert forecast emitted by FURROW-R, and runs each strategic query
  with a full (warm-tier) or summary (weekly-tier) plan chosen by deadline feasibility and energy.

Everything is evaluated on the real **Cook Agronomy Farm** sensor network (42 stations x 5 depths,
2011-2012; Gasch et al., 2015, 2017) with task costs measured by executing the real retrieval
operators, inside a discrete-event simulation of a 200-farm edge-fog-cloud platform.

## Quick start
```bash
pip install -r requirements.txt
python scripts/download_data.py && python scripts/prepare_data.py
python -m pytest -q
bash scripts/run_all.sh calib A B C D E F artifacts   # ~3 h on 2 cores
python paper/build_docx.py                            # manuscript .docx
```
Single experiments: `python scripts/run_simulation_grid.py D_ablation --seeds 5`.

## Reproducing the paper
See `docs/reproduction_protocol.md`. Every number in the manuscript is read from
`results/processed/paper_values.json` or from `results/tables/*.csv`, which are generated by
`scripts/generate_paper_artifacts.py` from the raw run files in `results/raw/`.

## What is measured and what is assumed
Measured on real data: soil-water readings, delivery gaps, ground-truth grades, every strategic
and verification task's CPU time, bytes and partition count, and the summary-plan answer errors.
Assumed (documented in `config/default.yaml`, varied in Experiments E-F): reporting intervals,
number of farms (time-shifted replicas of one real network), query arrival rates and deadlines,
node speeds, power and prices, network latencies and bandwidths, poll latency, estimation noise.
